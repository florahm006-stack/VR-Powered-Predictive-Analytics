# Architecture Notes

## Assemblies

```
VRLab.Data        Dataset, DatasetLoader (CSV), StreamingDataFeed     [no deps]
VRLab.Charts      Chart3D base + Scatter/Line/Bar (GPU instancing)    [→ Data]
VRLab.ML          IPredictionBackend, Http / InferenceEngine / closed-form impls,
                  PredictionClient (failover facade)                  [→ Data, Unity.InferenceEngine]
VRLab.Interaction ParameterSlider, SliderGrabDriver (XRI grab→value),
                  Debouncer, VoiceCommands, HapticFeedback            [→ Unity.XR.Interaction.Toolkit]
VRLab.Scenarios   ScenarioBase, StockMarket, Forecasting              [→ Charts, Data, ML, Interaction]
VRLab.Core        GameManager, RigSetup, ComfortLocomotion, PC fallback [→ Scenarios]
VRLab.UI          WorldSpaceMenu, Billboard                           [→ Core, Scenarios, ML]
VRLab.Assessment  QuizSystem, LearningLogger                          [→ TMP]
VRLab.Tests.EditMode  CSV + fallback-math + chart round-trip tests    [→ Data, ML, Charts]
Editor (Assembly-CSharp-Editor)  LabSceneBuilder (scene composer CLI),
                                 RunTestsCli (batch test runner)
```

The scene `Assets/Scenes/Lab.unity` is generated by `LabSceneBuilder.Build`
(re-runnable, deterministic). Canvases use XRI `TrackedDeviceGraphicRaycaster`;
the scene EventSystem hosts `XRUIInputModule` so controllers can press buttons.

## Key design decisions

- **IPredictionBackend** hides where inference happens. `PredictionClient`
  health-checks the FastAPI service every 30 s and picks the best backend:
  `HttpPredictionBackend` (online) → `SentisPredictionBackend` (on-device ONNX
  via Unity Inference Engine, models in `StreamingAssets/Models`) →
  `OnnxPredictionBackend` (closed-form coefficients mirrored from
  `train_model.py`, always available). The UI shows which backend is active —
  important for low-bandwidth classrooms (brief step 7).
- **GPU instancing** for all charts: point transforms are rebuilt into a
  `Matrix4x4[]` and drawn with `Graphics.RenderMeshInstanced` — one draw call
  per chart, safe for Quest GPUs. Materials must set `enableInstancing = true`
  (caught by tests). Point budgets are clamped (`maxPoints`).
- **Sanitization at the boundary**: `DatasetLoader` skips malformed rows and
  clamps NaN/∞ so chart scales can never explode.
- **Debounce**: sliders fire debounced predictions (0.25 s) so dragging at
  90 Hz doesn't flood the ML service.
- **ScenarioBase** (`Enter`/`Exit` + Content-root activation) keeps scenarios
  prefab-friendly and later multiplayer-ready (Netcode).
- **Deterministic scene composition**: the scene is built by code
  (`LabSceneBuilder`), wired with `SerializedProperty` reflection helpers, so
  the scene can be regenerated/extended headlessly in CI.

## Data flow

```
CSV (StreamingAssets/Data/*.csv)
  → DatasetLoader → Dataset(series + bounds)
      → Chart3D.SetDataset / StreamingDataFeed ticks
Sliders (grab in VR via SliderGrabDriver, scroll on PC)
  → Debouncer → PredictionClient
      → HttpPredictionBackend → FastAPI (/predict/forecast, scikit-learn GBM)
      → SentisPredictionBackend → Inference Engine (demand_model.onnx)
      → OnnxPredictionBackend → closed-form coefficients
      → chart overlay + demand readout
QuizSystem / interactions → LearningLogger → persistentDataPath/*.csv (pilot data)
```

## ML service contract (ml-service/app.py)

| Endpoint | Input | Output |
|---|---|---|
| `GET /health` | — | `{status, models_loaded}` |
| `POST /predict/linear` | `{features:[...], horizon}` | `{predictions:[...]}` |
| `POST /predict/forecast` | 3 features `[price, marketing, seasonality]` → demand model (GradientBoostingRegressor, R²≈0.996); otherwise naive-drift forecast over a history window | `{predictions:[...]}` |

ONNX twins of both models are exported by `train_model.py` (skl2onnx) and
loaded by `SentisPredictionBackend` for offline parity.

## Testing

- **EditMode (11 passing):** CSV parsing (valid/malformed/NaN/empty),
  fallback-math validation vs. the same ground truth used to train the Python
  model, dataset→chart rendering (instanced, `PointCount` assertions),
  live-append growth, offline prediction round-trip.
- **CLI:** `RunTestsCli.RunEditMode` (batch-safe). PlayMode runs from the GUI
  Test Runner (headless batch play-mode hangs on this machine).
- **Manual acceptance:** both scenarios end-to-end on headset and PC; quiz + CSV
  log verification; menu buttons (now wired) and slider grabbing.
